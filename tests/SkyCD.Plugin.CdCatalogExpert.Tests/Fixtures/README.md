# CD Catalog Expert fixtures

All fixtures are synthetic and generated by the plugin writer itself
(`ZdcWriter`); no genuine CD Catalog Expert files are redistributed.

- `sample.zdc` + `sample.manifest.json` — the catalog from
  `ZdcFixture.SampleDatabase`: catalog index, two disc XML members, and one
  cover. The manifest pins member names, stored lengths, decompressed payload
  sizes, and the SHA-256 of every decompressed payload plus the whole
  container. `ZdcCheckedInFixtureTests` verifies the manifest and asserts the
  container rewrites byte-identically.
- `minimal.zdc` / `full.zdc` / `boundary.zdc` with matching
  `.expected.json` — grammar coverage fixtures. `minimal` is a catalog with an
  empty disc tree; `full` adds nested groups, metacharacters, CR/LF,
  Windows-1252 text, every disc attribute, a cover, an unknown attribute, and
  a `ulong.MaxValue` file size; `boundary` carries 160 files across multiple
  tree chunks. Each expectation file records the catalog name, media fields,
  files, directory count, member payload hashes, and expected warnings.
- `malformed/*.zdc` — missing disc-tree member, invalid GUID, invalid number,
  invalid encoding, malformed XML, excessive nesting, and a corrupt container.

Runtime-built fixtures (`ZdcFixture`) cover the rest: header offsets, record
types, checksum/CRC vectors, cross-chunk and multi-index-chain payloads,
multiple directory chunks, empty members, deterministic output, and the
grammar/writer cases exercised by the unit tests. Malformed runtime inputs are
produced by byte-level mutation of valid archives.
