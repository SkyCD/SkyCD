# Issue 512 — DiskCatalogMaker v5 catalog import

## Scope

Add native DiskCatalogMaker v5 import for `.dcmf` files and `.dcmd` packages,
including folder hierarchy, volume identity, item metadata, aliases, labels,
type/creator codes and thumbnail references. The existing
`diskcatalogmaker-text` plugin keeps handling text exports; other catalog tools
(WinCatalog, Disk Explorer, ADC, DICOM files named `.dcm`) must not be stolen.

## Deliverables

- `Plugins/SkyCD.Plugin.DiskCatalogMaker/DiskCatalogMakerV5Plugin.cs` —
  `IFileFormatPluginCapability`, `IContentAwareFileFormatCapability`,
  `IFolderAwareFileFormatCapability`; format ID `diskcatalogmaker-v5`.
- Parser pipeline: `DiskCatalogMakerV5BinaryReader` (bounds-checked little-endian
  reads), `DiskCatalogMakerV5Parser` (header/directory/tables/records),
  `DiskCatalogMakerV5HierarchyBuilder` (rows and hierarchy),
  `DiskCatalogMakerV5ThumbnailResolver` (object-path construction).
- Format-specific exceptions: corrupt catalog, unsupported version, catalog too
  large, missing package payload.
- [Format documentation](../plugins/diskcatalogmaker-v5.md) with field tables and
  sample offsets from a committed fixture.
- Synthetic fixture suite and 101 tests in
  `tests/SkyCD.Plugin.DiskCatalogMaker.Tests`.

## Behaviour

- **Files:** `.dcmf`/`.dcmd` are matched by extension and validated by the 32-byte
  header, so unrelated files are rejected even if the extension matches.
- **Packages:** a `.dcmd` directory is claimed only when `Catalog.dcm` exists and
  passes header validation; missing or invalid payloads surface as
  `DiskCatalogMakerV5MissingCatalogException` /
  `DiskCatalogMakerV5CorruptCatalogException`.
- **Thumbnails:** `Thumbnails/aa/bb/cc/dd.ext` paths are attached to item rows and
  marked resolved when the object exists; missing or absent objects never fail
  the import.
- **Unknown data:** unknown tables are preserved with warnings; unknown string IDs
  degrade to placeholders with warnings; malformed alias extra data stops alias
  parsing only.
- **Integrity:** overlapping/out-of-range tables, duplicate IDs, truncated
  payloads and invalid string encodings are hard failures. Warnings are capped at
  1000 entries and the report is marked partial when warnings occur.
- **Bounds:** 512 MiB payload, 4096 tables, 5,000,000 records per table, 4 MiB per
  string, 64 KiB retained alias extra data.
- **Read-only:** `WriteAsync` returns the standard not-supported failure and the
  parser opens no writable streams.

## Why a documented synthetic layout

No redistributable v5 catalog exists, so acceptance rests on a documented byte
layout, a field table with sample offsets, deterministic fixtures and
corruption/regression tests. The layout mirrors the issue's storage model
(`Catalog.dcm`, `TDCatalogFileV5*`, `TDVolume*TableV5`, four-byte table IDs,
UTF-8/UTF-16 string tables, thumbnail fan-out paths). Fixtures are generated by
`DiskCatalogMakerV5FixtureBuilder` and committed; a consistency test byte-compares
them with the generator.

## Tests

- Detection and host routing: header recognition with position restoration,
  rejection of text/DICOM/truncated/endian-mismatched payloads, and
  `FileFormatManager` resolution of `.dcmf`, `.dcmd` and `.dcmd` folders.
- Parser: empty catalog, Unicode hierarchy, labels/POSIX modes, type/creator
  codes, UTF-16 strings, aliases, unknown tables, full-path overrides,
  non-printable FourCC escaping, orphan volumes, packages as folders.
- Corruption: header/directory/table/record/string/alias validation paths.
- Thumbnails: path fan-out, extension normalization, resolution and duplicates.
- Plugin surface: progress and cancellation, package vs file reads, missing
  payload, read-only writes.
- Integration: `CatalogLoadService` + `FileFormatManager`, `MainWindow` row
  extraction, Couchbase persistence/reopen, `MainWindowViewModel` reconstruction
  and failure propagation for corrupt catalogs.
- Fixtures: checked-in manifest-free oracles, regeneration flag, byte
  consistency.

## Known limitations

- No real DiskCatalogMaker build was available for interoperability testing.
- `.dcmexr` sidecar metadata is not imported (independent follow-up).
- Legacy `.dcm`/`.toastcat` catalogs are out of scope.
- Thumbnail and QuickLook bytes are referenced, not copied.
- Header checksums are read but not verified.
